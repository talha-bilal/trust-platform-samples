4. How employees sign in (end-to-end flow)

From the user’s perspective, access is simple. Behind the scenes, Keycloak coordinates AD, MFA, and application trust.

Figure 2 — Authentication flow. First application login establishes an SSO session at Keycloak. Additional applications reuse that session.

  1. Employee opens a business application (e.g. service desk, portal).
  2. Application redirects the browser to Keycloak — no local login form.
  3. Employee enters Active Directory username and password.
  4. Keycloak validates credentials against AD via LDAPS.
  5. Employee completes MFA with authenticator app (one-time code).
  6. Keycloak issues OIDC/SAML tokens to the application.
  7. Employee works in the app. Opening another integrated app reuses the SSO session.

8. Active Directory integration

Active Directory remains your master directory. Keycloak federates users — it does not replace AD.

StepActionWho
1Create AD service account (read users & groups)Customer AD team
2Allow LDAPS Keycloak server → Domain ControllerCustomer network
3Configure LDAPS URL, bind DN, user search baseSecureLink
4Map AD groups to application rolesSecureLink + app owners
5Sync up to 300 users; test login & disabled accountsSecureLink

Validation tests before go-live

  • Valid AD user → successful login through Keycloak
  • Disabled AD account → access denied immediately
  • User added to AD group → correct role after sync
