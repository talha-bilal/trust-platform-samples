2. Technical approach

I operate on-prem Keycloak in production today: AD/LDAP federation, OIDC application SSO, and realm lifecycle at scale. This engagement uses the same architecture pattern — built to add users and applications without redesign.

Target architecture — centralized IAM; AD remains the identity source; new apps connect via standard SSO protocols.

3. Phase-by-phase delivery plan

Six phases aligned to the approved customer scope. Remote delivery over a 4–6 week window.

1

Discovery & design

  • Kickoff with IT and application owners
  • Validate AD topology, LDAPS, and SSO protocol per app (OIDC / SAML)
  • Technical design: realm, federation, firewall matrix, cutover plan
2

Platform deployment

  • Keycloak + PostgreSQL on customer infrastructure
  • TLS, admin RBAC, brute-force protection, session policies, logging
  • Backup baseline and health validation
3

Active Directory / LDAPS

  • LDAP user federation (bind account, search bases, username attribute)
  • Group-to-role mapping; directory sync
  • Validate login, disabled accounts, and group changes
4

MFA configuration

  • TOTP authenticator policy per agreed scope
  • Pilot enrollment with IT team; admin reset procedure documented
5

Application SSO (up to 8 apps)

  • Per app: client setup, metadata / redirect URIs, claims, logout
  • Support application owner UAT through sign-off
  • Includes agreed applications from customer scope (e.g. Dynamics, ServiceDesk Plus, Endpoint Central, portal, Temenos, and others as confirmed)
6

Testing & handover

  • Regression: AD, MFA, and SSO flows
  • Administrator guide, backup/restore procedure, knowledge transfer session
  • Implementation close-out documentation
